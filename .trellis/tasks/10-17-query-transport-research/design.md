## 实验拓扑与控制平面

- 独立命名 coordinator VM 与 disposable peers；使用独立 cookie、唯一节点名、低 scheduler 数。最多同时启动少量节点，不接触已存在的项目节点。
- 使用 `:peer` 的 standard_io 控制通道控制故障和收集证据，使断线后的查询/观测不依赖被测 distribution 通道。
- 故障结束前不经被测节点发起 RPC/remote monitor/IO；跨节点监控也可能建立连接，不能以这种观察证明不重连。
- 正常对照、故障组和必要的正向重连对照分别建新 peers，避免历史连接和缓存状态互相污染。
- 端点崩溃实验只在单独的 authority 测试 VM 内执行；人工终止、进程 kill 与 Supervisor 公开重启操作分别标识，不能混称同一种故障。
- 当前业务代码仅用于测试实例；创建 deterministic Agent，绝不调用模型网络服务。不通过私有业务 state 读取凭据或伪造 Ref。

## 场景矩阵

| 场景 | 必须观测 |
| --- | --- |
| 正常 list/lookup | 返回值、耗时、Agent PID/incarnation、worker 结束 |
| 远端函数阻塞及 Server 暂停 | 本地超时、远端 worker 是否仍活着、Server 恢复前后状态 |
| 调用方被终止 | 远端开始/完成事件、helper 退出时间、Agent 是否仍活着 |
| rex 暂停、请求超时、rex 恢复 | 实际 rex 邮箱/trace 路径、过期请求是否开始、晚回复去向 |
| 已断线后调用 | 连接事件、是否自动建连、无观测方污染 |
| 连接预检查后强制断线再发送 | 用屏障固定竞态，不靠 sleep 碰概率；检测重连 |
| 工作开始后或回复前断线 | 远端是否完成、回复/monitor 是否造成连接动作 |
| Endpoint 意外退出 | 原 Agent PID/incarnation、监督树相关 PID 是否更换 |
| 小规模并发/重复查询 | 查询 helper 和 mailbox 是否回到基线，粗略时延/进程增量 |

可复现的竞态场景至少独立重复三次。超时优先使用短预算加事件屏障；现有 Endpoint 的固定 5 秒预算保持不变。不是所有场景对每个对象都有意义，不适用单独注明，不能记为通过。

## 数据和结论契约

- 每个场景记录 ID、执行对象、运行时版本、命令、重复次数、预期、观测事件、elapsed、worker/Agent/connection 状态、清理结果。
- 跨 VM 不比较 monotonic timestamp；各 VM 自计耗时，以屏障确定先后。无硬实时保证。
- 原始记录保存为 JSONL（必要时 ETF 辅助文件），包含实际失败/阻塞；不记录 cookie、凭据或无关历史。
- 分开回答：是否不等回复、是否丢弃晚回复、是否停止本次 worker、是否阻止排队请求未来启动、是否影响 Agent、是否自动重连。
- 耗时及进程计数仅作诊断，不作为生产性能 benchmark 或物理跨机保证。

## 生态调查方法

以官方 HexDocs、OTP 文档、项目源码、Hex 发布记录与仓库维护状态为一手来源，注明核查日期和版本。比较需求覆盖、调用语义、故障传播、取消/超时、连接行为、注册一致性、依赖成本、OTP29/Elixir1.20 兼容证据和迁移复杂度。文档声称的兼容不能等同于本地实测兼容。

优先寻找不增加依赖的最小方案；gen_rpc 不等于取消协议，Syn/Horde 不等于权威实例 lookup，libcluster 不等于查询协议。缺少解决能力时允许结论为“不适用”，不引入分布式注册表替代现有 Registry。

## 风险和退出

- rex/agent 被 suspend 必须在 finally 中恢复；结束时停止本实验拥有的 peers。
- 不停止共享 epmd、不 kill 未登记进程、不复用生产 cookie。启动控制 VM 设置全局超时与清理机制，记录残留检测。
- 查询与 Agent “无影响”按只读/故障隔离评估，不承诺零资源占用。
- 推荐中分别列出：保留既有严格保证的最小方案、若接受有限后台完成的简化方案；未批准前不修改当前契约。
