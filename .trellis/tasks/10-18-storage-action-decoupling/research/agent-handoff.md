## Transactions, fencing and continuation

Create/fork create distinct random dispatch scopes in the same Agent command transaction. Agent transition reads take FOR UPDATE on PG (SQLite immediate writes serialize). Prepare checks position, active turn, sources/inheritance, body-free control and artifacts, invokes neutral Actions participant for each member with Agent scope/current generation as epoch, inserts association and preparation events and saves command response inside one transaction. Records.transact rolls back every table on any error. Command replay returns its original response after later transitions, including after reauthorization; no request/source identity is rewritten.

Restore locks Agent before neutral scope rotation and commits generation+epoch together. Claims remain neutral Actions work and never query/lock Agent. Existing claim-first semantics remain: claimed work can retain late evidence/results, but cannot be explicitly resumed as pending work or consumed under a new generation without accepted adoption.

Explicit continuation verifies Agent/turn under the Agent lock. Accepted work advances only association owner_generation; accepted Result/evidence/Operation version remain unchanged. Pending work calls `DispatchScopes.reauthorize_in_transaction` with exact scope/from/to epoch, operation/attempt IDs, description digest, Operation version and attempt version, then updates association owner_generation in the same transaction. A failed sibling rolls back prior scope reauthorization and association changes. Claimed unresolved work refuses. Fresh fetch returns updated lock_version and scope epoch; Server rebuilds prepared identity with both scope fields and Durable.persistence supplies them. Runtime therefore checks refreshed binding again at claim. Lock order remains Agent -> scope -> Operation; acceptance only uses Actions locks.

Loader, ContextBuilder, History, TraceSnapshot and Inheritance now use Agent projections and explicitly separate operation-event reads. Fixed Agent/Operation high waters, preparation/accepted digests, owner/turn/step/source validation and optional-cache fallback remain. Exact Core adapter/read-stop counts pass. Trace envelope remains format2 because existing exported reference/JSON semantics remain unchanged; dataset format is separately3. No cloned Operations/attempts/commands or parent-log recursion on fork.
