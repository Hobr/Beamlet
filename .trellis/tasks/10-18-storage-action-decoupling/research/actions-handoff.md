# Actions persistence and Runtime handoff

Actions lane complete on refactor/storage-action-decoupling, baseline a8acffd. No commits, staged files, task-status changes, Agent/Node/Server edits or real dataset operations. Foundation edits preserved. This is a component milestone, not full migration/release acceptance.

## Ownership and installation contract

New no-Application-callback app `beamlet_actions_storage`, module prefix `Beamlet.Actions.Storage`, depends directly on Actions, Storage, Ecto/SQL/SQLite/Postgrex/JSON. Runtime declares Actions Storage and Ecto directly; root backend_apps includes Actions Storage. Actions-only runtime closure was started independently from apps/beamlet_runtime and contains no Agent, Node or Server application and starts no Repo (`/tmp/actions-closure.log`).

Trusted format3 descriptors from `Profiles`:

- `authority/0`: profile `actions-authority`; ordered components foundation1, actions-authority1; migrations foundation ID1 (`Beamlet.Storage.Migrations.FoundationV1`), ID100 (`Beamlet.Actions.Storage.Migrations.AuthorityV1`, component actions-authority).
- `journal/0`: profile `actions-journal`; ordered components foundation1, actions-journal1; migrations foundation ID1, ID200 (`Beamlet.Actions.Storage.Migrations.JournalV1`, component actions-journal).
- `authority_component/0`, `authority_migration/0`, `journal_component/0`, `journal_migration/0` publish exact entries for explicit trusted composition. Agent authority MUST choose its own stable profile (design suggests `agent-authority`), compose `[Installation.foundation_component(), Profiles.authority_component(), agent_component]`, and `[Installation.foundation_migration(), Profiles.authority_migration(), agent_migration]`. Agent migration ID must be >100 (recommend reserve 300 for Agent v1); it must not rename/change Actions migration identity. This lane does not allocate Agent IDs or silently select an Agent profile.
- Neutral opt-in instances: `SQLiteAuthorityRepo`, `PostgresAuthorityRepo`, `ExecutorJournalRepo` (SQLite). Each uses `Beamlet.Storage.Repo`; initialize/open/verify take Foundation's explicit descriptor/dataset options. SQLite requires database and distinct peer_database. No default dataset/profile or migrations at application load.

Authority exact base tables: artifacts, storage_metadata, schema_migrations, dispatch_scopes, operations, executions, execution_evidence, operation_events. Journal: foundation base plus journal_attempts. No Agent table or foreign key. New authority migration retains operation/attempt/evidence uniqueness and FK constraints; accepted_evidence edge is cyclic on SQLite and installed after table creation on PG. Operation events are separate, uniquely ordered by operation_id/seq, with operation.prepared and operation.result_accepted vocabulary.

## Models and neutral projections

`Schema.Operation`: id, dispatch_scope_id, dispatch_epoch, description, description_digest, accepted_result, accepted_evidence_id, lock_version, history_seq, schema_version, recorded_at. No owner/turn/step/role/ordinal/toolcall/prepared_seq/sources or other Agent metadata. Scope UUID stays fixed; epoch changes only through explicit pending reauthorization, which increments Operation lock_version. Description/digest remain immutable.

Execution: attempt_id, operation_id, executor_id, executor_boot_id, description_digest, dispatch_state (prepared/send_claimed), observation, budget, lock_version, recorded_at. One attempt per Operation. ExecutionEvidence: id, operation_id, attempt_id, executor_id, evidence_id, digest, content, resolution, recorded_at; unique executor_id/evidence_id. OperationEvent: id, operation_id, seq, type, schema_version, payload, recorded_at.

`OperationRecords.fetch(repo,id)` returns `{:ok, %{"operation" => neutral_operation_map, "attempt" => neutral_attempt_map}}`. Struct metadata omitted, keys strings, timestamps ISO8601. Agent Storage must JOIN its own agent_operations to project old orchestration fields; never add them back to Actions schemas.

`Codec` owns Actions bounds: operation1MiB, event/result4MiB, journal_artifacts24MiB. It calls Foundation Codec using a newly supported positive integer byte bound. Canonical sorted-key UTF8 JSON/hash bytes, depth32/nodes100000, duplicate-key and credential-field rejection remain identical. Actions owns its JSON parameterized Ecto type, Records helpers and RecordChangeset; it does not import old Agent-aware Records/Events/RecordChangeset. Foundation Artifacts/References/Transaction remain generic shared facilities. TerminalArtifacts limits/protocol unchanged (64 items, 16MiB total decoded, 24MiB encoded); journal total terminal transaction budget32MiB.

## Exact APIs

All modules below use the `Beamlet.Actions.Storage` prefix. Facades return safe error atoms, no SQL detail, no retries or external effects in transactions.

`OperationRecords.prepare(repo, %{operation: %{id: uuid, description: string_key_map, dispatch_scope_id: uuid_or_nil, dispatch_epoch: count_or_nil}, attempt: %{attempt_id: uuid, executor_id: uuid, executor_boot_id: uuid, budget: json}})` commits once. Scope keys may be omitted together. Description permits kind/protocol_version/payload/refs/budget/claims/safety; requires protocol_version1, nonempty kind, map payload. Description artifact references verified in the write transaction. Identical operation+attempt replay returns original preparation; changed identity conflicts.

`prepare_in_transaction(repo, same_attrs)` requires caller-owned transaction and validates everything. It returns tuples without independently committing or rolling back. The outer facade MUST rollback any participant error (including across batch members). `insert_prepared` is private; no raw bypass API.

Prepared response string keys: operation_id, description_digest, attempt_id, attempt_version0, lock_version0, dispatch_state prepared, dispatch_scope_id, dispatch_epoch.

`claim_dispatch(repo, %{operation_id: uuid, attempt_id: uuid, expected_version: attempt_version, expected_operation: %{description_digest: hex_digest, lock_version: operation_version, dispatch_scope_id: uuid_or_nil, dispatch_epoch: count_or_nil}})`. expected_operation is optional for neutral callers claiming the current stored binding; when supplied all four exact keys are required and checked under Operation lock. Runtime ALWAYS supplies it. This prevents a stale prepared submission from claiming work reauthorized after its initial validation. Missing row/changed binding/version/state/accepted Result => conflict; stale scope epoch => stale_epoch. Single CAS increments attempt version and marks send_claimed.

`record_evidence(repo, %{id, operation_id, attempt_id, executor_id, evidence_id, content, resolution: optional_json})`: validates identity and actual attempt/executor binding, digests content. Executor/evidence identity replay must preserve operation/attempt/content digest/resolution. Late evidence ignores epoch and remains valid.

`accept_result(repo, %{operation_id, expected_version: operation_version, result: json, evidence_id: optional_authority_evidence_row_id, artifact_ids: optional_list})`: validates Operation/evidence/artifact binding; CAS increments operation version and event high-water once. Identical accepted result+evidence replays regardless old expected version, changed acceptance conflicts. Response: operation_id, accepted_result, accepted_digest, accepted_evidence_id, lock_version, history_seq. Acceptance never acquires scope or Agent locks.

`DispatchScopes.create(repo,%{id: uuid})` => string map id/epoch0. `current(repo,id)` safe read => same shape. `rotate(repo,%{id: uuid,expected_epoch: count})` => incremented epoch; stale_epoch on mismatch. `create_in_transaction` / `rotate_in_transaction` have the same attrs/return shapes, require caller transaction and validate inputs.

`DispatchScopes.reauthorize_in_transaction(repo,%{scope_id,from_epoch,to_epoch,operation_id,attempt_id,description_digest,expected_version,attempt_version})` requires caller transaction, exact attrs and validated identities/versions/digest; to_epoch > from_epoch and equals current scope epoch. Takes scope SHARE then Operation UPDATE. Requires same scope ID/from epoch/digest/Operation version, unaccepted Operation and exact prepared attempt/version. Updates only dispatch_epoch and Operation lock_version (+1). Response string keys operation_id, lock_version, dispatch_scope_id, dispatch_epoch. Caller obtains the unchanged attempt identity/digest/version from its saved association or fetch, constructs the refreshed prepared response, and supplies refreshed Persistence scope/epoch. Claimed/accepted/mismatched work returns conflict. Agent should skip accepted work during continuation rather than call reauthorize; old AgentRecords adoption allowed accepted work to advance owner_generation, which now belongs solely in Agent associations. Agent generation/source/turn checks remain Agent responsibility.

PostgreSQL claim reads fixed scope ID, locks scope FOR SHARE and checks current epoch, then locks Operation FOR UPDATE, verifies optional expected binding, then attempt CAS. Rotation takes scope FOR UPDATE and increments. Reauthorization also scope->Operation. Agent callers must obey Agent->scope->Operation, never call rotation after acquiring Operation locks. SQLite immediate transactions serialize writers. Restore/rotation-before-claim refuses pending old epoch; claim-first preserves already claimed semantics; late evidence/acceptance are independent. No cancellation/exactly-once guarantee for work already sent.

`ExecutorJournal` protocol moved with unchanged neutral inputs/results: claim_start, record_stop, record_terminal, acknowledge, mark_unknown_after_restart (all repo/attrs); fetch(repo,authority_id,attempt_id). Unique authority/attempt, identity-bound start replay, first stop cause, atomic terminal/attachment/receipt, idempotent terminal/ack replay, monotonic unknown_after_restart preserved. Unknown never authorizes a second start or terminal fabrication. `TerminalArtifacts.encode/1`, encoded_size/1, content/2 retained under new namespace.

## Runtime wiring

Persistence fields: authority_repo, journal_repo, authority_id, executor_id, executor_boot_id, dispatch_scope_id, dispatch_epoch. Scope optional but UUID/nonnegative epoch must appear together. `owner` field removed; no Agent type/config/callback/query. `Runtime.submit owner:` remains PID lifecycle ownership.

Normal prepare supplies neutral description and optional scope, no sources. Prepared submit validates actual description/digest, operation+attempt IDs, both versions, actual and expected scope+epoch, executor+boot, prepared state and absent accepted result. Coordinator passes expected Operation binding into claim again under lock, closing validation-to-claim reauthorization races. Gateway/coordinator/evidence use new journal/OperationRecords aliases; generic Admission stays Foundation. Credentials remain transient and canonical descriptions unchanged.

README updated with explicit profiles and APIs. Runtime durable fixture uses Actions-only tables; generic handler kind durable (not model/tool). Prior Agent-specific sibling assertions replaced by scope epoch invariance, and old generation fencing test adapted to scope rotation. Agent owner must restore the Agent generation/CAS assertions in its own tests when integrating; this is not full Agent regression coverage.
