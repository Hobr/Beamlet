# 完善全项目公共与私有类型契约

## 目标与用户价值

为 Beamlet umbrella 建立准确、可维护、能被静态分析使用的类型契约，降低跨应用调用、复杂状态流转与错误处理的隐式约定。用户明确要求公共 API 与私有函数一并完善；不能仅以工具通过或声明数量作为完成依据。

## 背景与证据

- 当前 13 个应用、148 个生产 `.ex` 文件。AST 扫描的显式声明为 `@spec` 0、`@type` 7、`@callback` 5、`@typedoc` 0、`@opaque` 0、`@typep` 0；不含框架宏生成声明。
- 审查环境为 Elixir 1.20.4 / OTP 29；默认 Dialyzer 与格式检查通过，额外 `unmatched_returns` 检查产生 68 条告警，尚未逐项定性，不等价于 68 个业务缺陷。
- 已有 pre-commit 与 `scripts/deployment/check-local.sh` 检查入口，未跟踪 GitHub Actions workflow。
- 完整来源、命令结果及证据限制见 `research/audit-baseline.md`。

## 范围与已确认决策

- 覆盖项目维护的全部 `apps/*/lib/**/*.ex`，包括公共/私有函数、自有 callbacks、委托、宏模板与领域结构；框架生成项明确分类。
- 用户已同意：严格保持外部行为、错误原因、持久化格式与进程协议不变。允许修正类型声明、补充契约及做行为等价调整；真实业务缺陷先记录证据和影响，另行确认，不视为本任务自动授权。
- 用户已确认：不新增 GitHub Actions CI，仅强化现有本地/提交检查入口。
- 本任务为一个共同验收的契约强化目标，按现有应用依赖分层增量实施，不将部分应用完成宣称为全项目完成。

## 需求

### R1 — 公共和私有函数契约完整性

对全部自有生产模块建立按模块/名称/arity 的覆盖清单。自有公共函数、私有函数、delegates 与 callback 实现均应有准确显式契约。多 clauses、guards、default wrappers、独立 function head、嵌套模块和宏/quote 模板按实际语义归属，不按源码行数或条款数量冒充函数数量。无法或不应重复声明的框架/生成项必须精确列出原因，不静默遗漏普通私有函数。

### R2 — 领域模型与跨应用契约精度

对稳定的请求、响应、事件、选项、状态、身份句柄、持久化边界与错误结果提供有意义的类型表达。稳定结构不应退化成无说明的 `map()`、`term()`；真正开放的数据、任意输入验证器与扩展点保留正确宽度。按实际需要使用远程类型、联合、参数化、私有、opaque 类型及文档，不为使用特性制造抽象或错误隐藏合法字段访问。

类型表达能力以当前工具链为限：string-key JSON 的精确字段关系、字符串枚举及字节/深度/安全约束仍由运行时验证器和测试保证，不为了静态表达改变现有 wire/storage 数据表示。

### R3 — 修正已有类型语义偏差

核对类型与有效数据、构造器、校验函数及中间态一致。已知问题为 `apps/beamlet_actions/lib/beamlet/actions/operation.ex:18–22` 中 credentials/claims 的 required association 声明与有效空 map 数据不一致；应使合法空 map 的类型表达准确，不改变其既有有效性。

### R4 — behaviour 与错误处理约束

细化自定义 callback 的稳定数据形状，核对实现契约，避免只用 `map()` 掩盖字段及变体约束。审查基线 68 条及新增结构化返回值告警，区分必须处理的错误与有意 best-effort/副作用调用。不能为了消除告警添加无意义匹配、隐瞒真实失败或削弱断言；涉及真实行为修复按已确认的兼容性决策另行处理。

### R5 — 有效、可持续的检查

形成可重复的公共/私有函数契约覆盖门禁，防止新增函数无意缺失契约，并集成至既有本地/提交检查。强化现有 Dialyzer 检查，包含经过分类处置的 unmatched-return 检查；保留默认及 unknown 检查。更新项目类型约定。

不得通过全局忽略、排除应用、关闭检查、忽略失败退出码或宽泛声明伪造通过；必须区分框架生成代码和有意开放边界。覆盖门禁也不能仅凭声明存在证明契约语义准确。

## 验收标准

- [x] AC1 / R1：所有自有生产函数纳入模块/名称/arity 覆盖核对；公共、私有、delegates、自有 callback 均有契约，生成/特殊项精确可审计，无普通私有函数漏项。
- [x] AC2 / R2、R3：关键领域结构与跨应用调用使用准确可复用类型；Operation 空 map 等已知偏差消除；有效输入、错误结果和合法中间态没有被错误排除；不虚构 string-key JSON 的静态表达能力。
- [x] AC3 / R2、R4：Model、Tool、Handler callback 与实现相符；稳定的请求、响应及状态变体有实际约束，不是批量补无意义 `term()`。
- [x] AC4 / R4、R5：基线 68 条与新增 unmatched-return 告警有逐项处置及分类说明；包含选定增强检查的 `mix dialyzer` 通过且无屏蔽跳过。真实行为缺陷未确认前不擅修、不虚报该项完成。
- [x] AC5 / R1、R5：覆盖门禁对新增缺失公共/私有函数、去掉 spec、default/multi-clause/nested/delegate/quote 等场景有正负测试，缺失或无效特殊项返回非零，并接入现有检查入口。
- [x] AC6 / R1–R5：格式、warning-fatal 编译、适用现有测试与静态检查通过；全范围最终核对无行为、错误标签、协议、schema 或测试断言语义变更。记录执行/跳过/环境限制和现有 PLT 与 fresh project PLT 的区别，不能只用默认零告警证明正确。
- [x] AC7 / R5：项目规范记录类型归属、公共/私有函数、开放输入、callback、opaque、泛型、错误结果、JSON 表达限制及有意丢弃返回值约定。

## 不在范围内

- 新增 CI workflow 或配置仓库外强制门禁。
- 未另行确认的业务缺陷修复、公开 API 变更、schema/协议迁移、进程状态机或安全边界调整。
- 对依赖源码、框架自动生成代码逐条补手写声明；为追求特性数量强行使用 opaque、参数化类型或新增业务抽象。
- 用 typespec 替代运行时校验、安全边界、大小限制或持久化一致性检查。
- 已归档任务、研究快照、benchmark、测试 DSL 的全量类型化。辅助测试模块若编译或检查明确要求修改，必须说明必要性，不扩大为测试代码全量改造。
