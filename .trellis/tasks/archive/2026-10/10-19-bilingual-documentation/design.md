# 文档与注释设计

## 文件和语言组织

沿用仓库已有的 `_zh.md` 约定：`README_zh.md` / `README.md`、`GLOSSARY_zh.md` / `GLOSSARY.md`、`HOST_zh.md` / `HOST.md` 等。在原目录增加语言对，不复制源码或重构文件布局。英文为现有无后缀文件，中文为同目录 `_zh.md`；已有 `architecture_zh.md` 保持原路径。

根 README 引导到中文入口、十三个应用及使用指南。当前维护的设计文档保留“设计意图/已实现状态/证据限制”的区分。历史研究材料作为参考链接，不改写历史结论。

**用户已在中文阶段完成后放弃英文阶段**，因此只交付中文文件，并只链接已经存在的目标：不产生指向尚未创建英文文件的断链，也不为缺失的英文 README 建立占位文件。既有英文原样保留，不视为已完成的英文版本。

## 源码文档属性和注释

公开模块使用 `@moduledoc` 说明职责、所有权、启动前提、依赖边界及使用入口；公开函数/宏/回调使用对应文档属性说明用途、参数、返回、错误、执行副作用和边界，重复信息通过链接复用。稳定公开类型补充 `@typedoc`，不修改类型声明或函数签名。

每个文档属性保持单一属性，新增或完善的中文说明在前，既有英文（如有）保留在后；同一个默认参数函数只说明最大源码元数，避免覆盖属性和重复包装函数。普通注释采用中文行/段，必要处保留原有英文。

只新增中文翻译，不编写新的英文翻译。既有 doctest 示例保留可执行原文。术语与标识符分离：如解释 Operation/Result/Ref 时补中文含义，API、错误标签和持久化字段仍保留原拼写。

内部隐藏模块保持 `@moduledoc false` / `@doc false`；普通注释解释事务、有限等待、资源归属、时序、幂等、执行不确定性和不重试等原因，不将内部函数公开化。不改 Gettext 字符串或目录。

## 覆盖和证据边界

`research/coverage.md` 清点生产源文件、文档语言映射及每个文件的审阅状态。实施时逐文件阅读正文与关联调用方/测试，将公共模块和 API 分组写入详细覆盖项；隐藏/框架回调/简单结构的说明决策写明理由。文件清单不是已经完成源码语义审阅的证据。

文档命令只使用根 umbrella 支持的入口；依赖要求来自 flake/manifests，运行与发布参数来自现有 config、部署样例和脚本，不根据目标架构猜测接口。不为文档新增 ExDoc 等依赖或生成发布站点。

## 兼容性与回滚

不触碰运行表达式、字符串消息、配置值、规范、回调签名或持久化格式。比较基线与变更后的 Elixir AST，递归忽略位置元数据及 `@doc` / `@moduledoc` / `@typedoc`，其余结构必须相同；脚本与模板的注释由差异审查补充核对。对语义差异停止并回退对应文档编辑，不进行附带重构。只撤回本任务拥有的文档/注释差异，不覆盖其他人的改动。

验证报告形成固定中文基线；如后续发现中文有误，先修正中文并重新验证相关内容，再更新覆盖记录。
