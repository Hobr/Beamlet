# 完善项目中英文文档与代码注释

## 目标与用户价值

让使用者能够根据文档运行 Beamlet，让维护者能够理解应用边界、公共接口及关键逻辑的约束。

原始需求为先中文、后英文两阶段交付。**用户在中文阶段完成后明确表示“放弃英文”**，因此本任务最终交付范围为中文文档与源码中文说明；英文阶段不再实施，也不再补齐缺失的英文文档。

## 背景与证据

- `README.md:3` 标识项目仍处于 WIP；原根 README 主要罗列构建和检查命令，缺少项目简介、应用导航与完整运行路径。
- 十三个 Elixir Mix umbrella 应用，`apps/*/lib/**/*.ex` 共 148 个生产源文件；文件数不代表模块数。
- 六个应用原已有 README；Web 另有两个专题文档，部署脚本也有 README。覆盖不均，已有文档不等于完整使用指南。
- `architecture.md` / `architecture_zh.md` 描述目标架构，不能直接当作全部已实现的能力。

## 需求（最终范围）

- R1：完善根文档与十三个应用的中文文档入口，解释实际职责、依赖、开发环境、启动/调用前提和验证方式。
- R2：逐文件审阅生产源码的模块、公共函数/宏/回调及公开类型；补齐中文使用方式、输入输出、重要错误与生命周期说明。必要时为配置、示例脚本和复杂内部逻辑增加解释性中文注释。
- R3：说明必须与实际源码、配置和测试一致，保留现有有效约束，区分已实现能力、目标设计和未验证事项。
- R4：只修改文档、文档属性和解释性注释，不改变业务行为、API、依赖、持久化格式或文档可见性边界。
- R5：覆盖记录逐项标明完成、已充分说明、内部隐藏或无需补充的理由；不能以文件被编辑过代替文档完整性。

## 已撤销的范围

- 英文文档与英文源码注释不再补齐；七个缺失英文 README 的应用保持现状。
- 英文子任务 `../10-19-documentation-en/` 已按用户决定撤销并删除，未产生任何实施改动。
- 源码文档属性当前为“中文说明 + 保留的既有英文”，不构成完整双语版本；后续若要补英文，需重新取得授权并新建任务。

## 范围与排除项

覆盖根 README、术语表、架构中文版、当前维护的架构/持久化中文说明、十三个应用的中文 README、Web 中文专题、部署使用中文说明，以及第一方生产源码和相关配置/脚本中的解释性注释。

不逐行复述代码，不为文档工作增加业务测试或文档依赖；不修改生成资源、第三方依赖、历史研究/任务/日志、Trellis/代理说明或产品界面翻译。保留 `@doc false` / `@moduledoc false`；隐藏模块只增加普通注释，不扩大公共接口。未声称未执行的外部服务、物理跨机或部署验收已通过。
