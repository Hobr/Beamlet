# 执行计划

## 前置门槛

- [ ] 用户明确批准父任务及两个子任务的最终规划；先激活本任务。
- [ ] 读取父任务 PRD、design.md、implement.md、共同覆盖清单及相关应用规范；上下文清单已配置。

## 有序步骤

1. 逐文件审阅并细化公共模块/API/关键内部约束的覆盖项，对照调用方与测试。
2. 完善中文根 README、术语导航、十三个应用 README 及维护中的专题文档。
3. 按 Actions/Harness、Core/存储、Runtime/Agent、Node/Hosts/I18n 分批完善中文源码说明，保留有效英文。
4. 核对每批链接、示例、命令和覆盖状态，运行父任务 implement.md 中适用的格式、编译、契约及 AST 检查；语义不清时先查源码。
5. 收尾按父任务质量计划记录静态检查及所需测试，生成本任务 verification.md，分别列出通过、失败、未执行与原因。
6. 保存中文基线，更新覆盖清单并报告中文完成；只有验收通过后才转入英文任务。

## 检查与回滚

具体命令及适用范围遵循 [父执行计划](../10-19-bilingual-documentation/implement.md#验证)，不新增依赖或业务测试，不运行有外部副作用的文档示例。每批保留可审阅差异；不改行为来消除检查失败。父需求如有实质变化，先更新规划再重新审阅。
