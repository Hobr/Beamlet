# Internationalisation (Web and CLI Copy)

## 1. Scope / Trigger

Use when adding or changing user-visible copy in the Web UI or the CLI, adding a
locale, or touching the Gettext catalogues. Business strings that are protocol
values, config keys, log lines or internal reason atoms are out of scope.
Sources: `apps/beamlet_i18n/`, `apps/beamlet_web/lib/beamlet_web/locale.ex`,
`apps/beamlet_cli/lib/beamlet/cli/{gettext,locale}.ex`, and the `priv/gettext`
directories of the three apps.

## 2. Signatures

```elixir
# shared (both surfaces), runtime functions:
Beamlet.I18n.gettext("Refresh")
Beamlet.I18n.dgettext("errors", "timeout")
Beamlet.I18n.Vocabulary.status(:running)           # declared words only, else passthrough
Beamlet.I18n.Locale.normalize("en-US")            # "en" | "zh_CN" | nil

# app-owned copy, extraction macros imported from the app backend:
use Gettext, backend: Beamlet.Web.Gettext          # then gettext("...")
use Gettext, backend: Beamlet.CLI.Gettext
```

## 3. Contracts

Three backends, one owner per msgid:

| Backend | App | Owns |
| --- | --- | --- |
| `Beamlet.I18n` | `beamlet_i18n` (leaf; Gettext only) | words used by both surfaces: status/reason vocabulary, generic actions/headers, locale canonicalisation and default |
| `Beamlet.Web.Gettext` | `beamlet_web` | Web-only titles, descriptions, form labels, server feedback |
| `Beamlet.CLI.Gettext` | `beamlet_cli` | help body, CLI-only headers, terminal prompts |

Rule: a msgid both surfaces need lives only in the shared catalogue; single-surface
copy never enters it. The five msgid sets (shared default/errors, Web default/errors,
CLI default) are pairwise disjoint, and this is a test-enforced invariant, not a
convention.

Shared default-domain words are declared once in `Beamlet.I18n.Catalogue` (via the
extraction macros) and resolved at runtime through `Beamlet.I18n.gettext/2`; a value
outside `Vocabulary`'s closed lists is passed through unchanged, so an internal atom
never becomes a msgid. Web/CLI never register the shared backend, so per-app
extraction cannot prune shared entries.

Locales: `zh_CN` (default) and `en`. Canonicalisation lives only in
`Beamlet.I18n.Locale.normalize/1` (`zh`, `zh-cn`, `zh_cn`, `cn` → `zh_CN`; `en`,
`en-us`, `en_US` → `en`; anything else → `nil`). Missing translation falls back to the
English msgid; no `nil`, atom, function or raw term may reach rendered copy.
`zh_CN` must translate every extracted msgid; `en` msgstrs may stay empty because the
msgid is English.

Web precedence: valid `?locale=` (canonicalised; persisted to the signed session) →
session `locale` → `config :beamlet_web, :default_locale` → `zh_CN`. The
`Beamlet.Web.Locale` plug sits in the `:browser` pipeline after `:fetch_session`;
LiveViews use its `on_mount/4` plus `on_params/3`. The switcher is a plain full-page
link that preserves the current path; there is no client storage and no client-side
translation, so copy already rendered at mount keeps its language until the next page
load.

CLI precedence: `config :beamlet_cli, :locale` → `BEAMLET_LANG` →
`config :beamlet_cli, :default_locale` → `zh_CN`. `:default_locale` ranks **below** the
environment variable because `config/config.exs` always sets it; otherwise the
operator switch would be unreachable. `:locale` is deliberately not part of the
trusted `BEAMLET_CONFIG` host schema. `Runner` installs the locale once before reading
stdin; command grammar, table columns/order/widths, output bounds and exit codes are
unchanged in every language.

Extraction: run `mix gettext.extract --merge` from the repository root only (the
recursive task visits every app, and each backend writes its own `priv`).
`mix gettext.extract --check-up-to-date` is the drift gate. Gettext 1.0.2 on Elixir
>= 1.19.3 force-compiles twice, so generated POT/PO files contain duplicated `#:`
reference lines and extraction prints a spurious `same :priv directory` warning; both
are deterministic upstream artifacts and must not be hand-edited.

## 4. Validation & Error Matrix

| Condition | Result |
| --- | --- |
| Unknown/typo locale (`klingon`, `zh_TW`) | `nil` → default `zh_CN`; never persisted to the session |
| Valid alias (`zh`, `en-us`) | canonicalised to `zh_CN` / `en` |
| No session and no query | `zh_CN` (shipped default), including CLI without config/env |
| Missing msgstr | English msgid fallback, no crash, no term leak |
| Reason/status atom outside the vocabulary | passed through unchanged (documented mixed-script case) |
| Msgid used by both surfaces but only in an app catalogue | catalogue ownership test fails |
| Shared lookup literal missing from the shared catalogue | catalogue ownership test fails |
| `zh_CN` msgstr empty for an extracted msgid | catalogue completeness test fails |
| POT out of date with source | `mix gettext.extract --check-up-to-date` fails |

## 5. Good / Base / Bad Cases

Good: add a shared status word to `Catalogue` + both shared POs, call
`Vocabulary.status/1`; add Web-only copy with the Web macro and its own PO.
Base: `en` msgstr empty and the English msgid renders as-is.
Bad: duplicate a msgid in the shared and Web catalogues, hand-edit generated `#:`
lines, or translate protocol tokens/config keys.

## 6. Tests Required

`apps/beamlet_i18n/test` owns the invariants: per-catalogue `zh_CN` completeness
against the POT, `en` key coverage, pairwise disjointness, shared-lookup literals
(including the declaration module) resolvable, and the declared vocabulary present in
the shared POTs. `apps/beamlet_web/test/beamlet_web/i18n_test.exs` proves the shipped
Chinese default on `/`, `/agents/new`, the workspace and all three admin pages, explicit
`en`, session persistence and switch-back, alias handling and unknown-locale fallback.
`apps/beamlet_cli/test/beamlet/i18n_test.exs` proves the CLI precedence chain, `Runner`
installation and that unknown reasons never leak. Web behaviour tests set an explicit
`en` session locale (ConnCase) and CLI copy tests pin `:locale`/`Locale.put("en")` with
`on_exit` restore, so assertions never depend on the shipped language.

Delivery evidence: Web 73 passed/5 excluded, CLI 25/1 excluded, i18n 15 passed;
umbrella 318 passed/34 excluded; format, warning-fatal compile, strict Credo, Sobelow,
existing-PLT Dialyzer (no refresh) and the extraction drift gate passed. The
implementation's `/tmp` gate logs are historical and unverified; the independent review
re-ran all of the above (its one fix: the daemon closure guard now forbids
`beamlet_i18n|gettext|expo`). No browser walkthrough was performed for this task.

## 7. Wrong vs Correct

Wrong: import two Gettext backends into one module (macro name clash) or call the
shared backend through a macro so extraction writes shared msgids into the app POT.
Correct: import only the app backend for app copy, and use the runtime
`Beamlet.I18n.gettext/2` functions for shared words. Wrong: put `:default_locale`
above `BEAMLET_LANG`. Correct: keep the env override above the shipped default so the
operator switch works.
