# 首版范围与模型收敛提案

状态: 核心取舍已确认, 其余分期为建议. 已确认暂停治理分支, 首版对无法安全解决的 Unknown/冲突保持 Open、提供事实读取,
暂不提供人工协调裁定接口. 下表其余功能分期和具体拆分设计尚非最终决议.
先确认现有模型对正常使用的覆盖、完整性及与 SPEC 的一致性, 暂不追求特殊情况下的绝对可靠;
完成这项检查及必要补全之前不执行依赖拆分. 不实现 Runtime/Ecto, 不移动 Quint 文件或删除已有测试.
已接受的 Q1-Q78 语义保留; 功能后置不等于放宽其安全约束.

## 1. 首版只完成一个闭环

提交独立 Effect -> 持久建立 Intent/Execution -> 向可跨设备的 Worker 派发并持久授权 -> 保存报告 ->
验证后接受唯一 Outcome 或保留可恢复的等待/不确定状态 -> 重启后重新发现工作或复用结果.
不同 Intent 可以并发. 不要求所有 Intent 自动终结, 不恢复 Agent 调用栈、业务等待集合或依赖图.

| 范围 | 建议首版必须具备 | 对应模型 |
| --- | --- | --- |
| IEO 与提交身份 | 不可变操作定义、稳定 Submission Key、Open/Closed、唯一不可变 Outcome; 同身份冲突不能覆盖定义 | 执行安全核心 |
| 分布式启动 | 每个 Intent 一个逻辑 Authority, 不要求全系统单中心; Worker incarnation/generation、lease、先持久授权再调用 | 执行安全核心 |
| 报告与判断 | 验证来源、保存及去重报告、持久后确认; 保留迟到证据和冲突, 不把报告直接等同 Outcome | 执行安全核心 |
| 等待与恢复 | Handler 支持时可登记 durable Pending, 不依赖常驻 Worker; 工作可由持久事实重新发现, 通知丢失不丢工作 | 执行安全核心 |
| 安全替代 | 未授权 Prepared 可在旧领取失效后重新领取; 已授权不确定尝试保持 Unknown, 再次执行须满足独立安全依据 | 执行安全核心 |
| 终结 | 合格结果与 History 原子提交; Cancelled 仅是逻辑终结, 不承诺外部停止/回滚; Closed 不再新建尝试或授权 | 执行安全核心 |
| 工程落地 | 延续 Ecto SQLite/PostgreSQL 范围, 不新增 Memory/ETS Storage; 设计原子存储 Interface、受限值 codec、可信消息入口与最小 Handler 契约 | 工程 SPEC/后端符合性测试, 不由 Quint 代替 |

首版对 Unknown、旧成功阻塞或未协调冲突提供持久事实读取, 可以保持 Open; 不提供任意人工改写结果的逃生口.
已确认首版暂不提供人工采用/排除或完整冲突协调裁定接口. 合法新证据仍可按核心规则接受;
没有足够依据时等待, 而不是自动 Failed 或重执行. 显式 Cancelled 仍遵守原控制面规则, 不用作伪造未执行证明.

## 2. 后置功能, 保留已确认约束

| 后置能力 | 后置不代表什么 |
| --- | --- |
| 人工采用/排除、完整冲突协调命令 | 不删报告、冲突或旧成功阻塞; 引入时仍须契约依据、审查版本、稳定命令身份、原结果重投与审计 |
| 自动协调规则的多版本登记、退役与治理 | 不允许旧 Operation 被静默换义; Operation Identity 的兼容版本与治理规则版本不是同一问题 |
| 部分取代、显式处置撤销及专属授权 | 不默认最后写入覆盖, 不恢复更早处置, 不改写 Outcome; 引入时遵守 Q73-Q78 |
| 计划 Authority 迁移的完整操作流程 | 首版仍保留迁移所需稳定身份与持久事实; 不通过复制数据库或本地 epoch 宣称已完成可靠撤权 |
| 完整归档/清理、管理 UI、策略治理 | 不默认 TTL 清除可让旧命令再次执行, 不改变已接受身份/原结果语义 |

强制接管、零停机、外部 exactly-once、通用 Workflow/Job 引擎继续是非承诺, 不是这次新增的延期决定.
后置能力不会因当前 Quint 已有场景而自动成为首版交付要求; 这些场景保留为参考规格与未来回归资产.

## 3. 模型按问题拆, 不按文件数量拆

| 模型职责 | 回答的问题 | 应依赖什么 |
| --- | --- | --- |
| 执行安全核心 | 授权、崩溃、Unknown、报告、替代与 Outcome 是否安全? | 执行状态、可信证据/安全依据与外部协议假设, 不依赖治理登记/撤销类型 |
| 协调命令协议 | 何时接受明确裁定? 过期审查、身份冲突、原结果重投是否正确? | 核心的证据/资格判断 Interface, 不要求核心理解命令缓存与规则注册表 |
| 治理扩展 | 版本、退役、取代、撤销与授权如何影响既有判断? | 协调命令语义与明确作用范围, 不绕过核心终结/重试守卫 |

这是拆分目标, 不是现状: 目前多个入口仍共享包含治理和观察快照的大 Ledger, 不能仅把入口分组便宣称隔离完成.
保持现有 model/quint 的分层布局、无环导入、单实例共享 fixture 与外层一次绑定; 验证见证不成为执行守卫或公开持久化 schema.
保留组合检查, 至少覆盖旧成功阻塞、协调与终结竞争、新证据使旧处置不适用、旧命令重投及治理操作不改写 Outcome.
不删除独立见证来换取更小文件, 不把拆分后各自通过误当作组合性质已成立.

## 4. 收敛顺序与完成标准

1. 对照已确认 SPEC 检查正常使用路径、模型完整性与假设. [正常使用审查](../quint/normal-use-audit.md)
   保留补全前的缺口; [正常闭环补全](../quint/normal-use-coverage.md) 已增加独立回调、提交身份/业务值、Handler 条件、
   失败停止策略与原子接受的最小抽象, 最新实际检查结果与边界见该记录.
2. 正常闭环补全保持停止/继续的示例策略, 不继续增加治理或灾难故障要求.
   实际 codec、认证与 SQL 并发另列工程验证边界, 不为了“模型完整”把实现细节全部塞入 Quint.
3. 正常覆盖验收后再实施依赖收敛. 当前 [切割计划](../quint/dependency-cut-plan.md) 仅作候选方案, 未执行物理拆分.
   保留原组合模型, 核对既有场景/反例的保留、迁移或明确替代, 不悄悄降低覆盖.
4. 完成首版消息/值域、Handler、原子存储命令与 SQLite/PostgreSQL 并发符合性 SPEC; 仍须单独授权才开始 Runtime 实现.

模型收敛完成不能只以文件数或行数减少衡量: 核心读者无需学习治理规则即可解释执行安全,
核心正常入口实际不导入治理模块, 核心与组合检查均可独立执行, 所有验证边界明确.
日常先使用 Mix 类型/场景检查和小预算抽样; 核心语义改动、跨层拆分和阶段交付再跑完整回归. 文档修改本身不触发全量采样.
Q77 的 185 个正常场景、60 个反例和 42,000 条抽样作为保留基线;
正常闭环补全另增加 40 个正常场景、七个 mutation 和四组默认各 1,000 条的抽样入口,
合计 225 个正常场景、67 条预期反例通过, 46,000 条正式抽样及额外 seed 的 10,000 条抽样未观察到所检查不变量违规;
实际配置/覆盖与可信前提见补全页. Q78 授权区分已记录但尚未新增验证, 不计入这些检查.
