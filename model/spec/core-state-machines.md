# SPEC: 核心状态机与结果接受

本文规定 Intent, Execution, Outcome 的状态, 证据与接受守卫. 首版对无法安全解决的 Unknown/冲突保持 Open 并提供事实读取.
协调/治理章节保留后置能力的约束, 交付边界见 [首版范围](first-release-scope.md).
首版逻辑接口和具体选择由 [原子存储命令](storage-command-contracts.md), [持久值与消息](persistent-values-and-messages.md)
及 [Handler/恢复策略](operation-handler-contracts.md) 细化; 物理字段, 数据库映射和特殊协议仍需实现设计.

相关文档: [领域语言](../../GLOSSARY.md), [RFC 0001](../rfc/0001-core-boundaries.md).

## 1. 范围与假设

- 核心处理独立 Effect 的提交, 执行尝试, 权威结果接受与恢复事实, 不恢复调用栈或 Agent 控制流.
- 每个 Intent 有唯一逻辑 Authority. 多 Coordinator 可以在同一权威存储规则下处理请求; 第一阶段不允许双边权威提交.
- Worker 必须遵守启动授权协议. 本文不证明不合作或恶意 Worker 不会直接调用外部服务.
- 数据库事务不包含真实外部执行, 外部系统也不默认提供幂等, 查询, 取消或 fencing.
- 第一阶段正式支持 Ecto SQLite 与 PostgreSQL, 不实现独立 Memory/ETS Storage.
  具体故障与掉电保证, 存储配置和复制保证尚未定义.
- 涉及组合状态的不变量以一致的已提交权威状态为对象, 不以分别读取的瞬时结果为对象.

## 2. Intent

| 状态 | 定义 |
|---|---|
| Open | 没有 Outcome, 逻辑操作尚未终结 |
| Closed | 已有不可变 Outcome, 逻辑操作已终结 |

合法终结转换为 Open -> Closed, 必须与 Outcome 和终结历史共同提交. 不允许 Closed -> Open 或替换已有 Outcome.
需要新的逻辑操作时建立新的 Intent.

Closed 不意味着所有外部操作已停止, 也不禁止保存迟到报告. Ready, Running, Waiting 和 NeedsReconciliation 等操作视图不是
Intent 生命周期状态. 首版工作发现从已提交的 Prepared/Waiting/Unknown 等事实投影候选,
定义见 [存储命令的读取与发现](storage-command-contracts.md); 具体索引, 分页与调度节奏仍由实现选择.

## 3. Execution

### 3.1 协议状态

| 状态 | 定义 |
|---|---|
| Prepared | 尝试已建立, 尚未授予启动许可 |
| StartAuthorized | 启动许可已持久化, 外部操作可能已开始 |
| Waiting | 已接受可恢复的等待登记, 不依赖常驻 Worker |
| Unknown | 已存在可能执行的依据, 当前证据不足以可靠继续处理 |
| Resolved | 已接受足以判断尝试结果的证据, 不一定被采用为 Outcome |

StartAuthorized 不是 Running 的同义词. Resolved 不表示报告绝对真实或未来不会有矛盾; 已知冲突必须阻止未经协调的自动终结.

### 3.2 首版路径与旁路投影

| 转换 | 触发与最低守卫 |
|---|---|
| Prepared -> StartAuthorized | Intent Open, Execution 当前合格, 完整 Worker token 有效, Handler/重试条件合格; grant 与绑定同事务保存 |
| StartAuthorized -> Waiting | 接受 Handler 契约支持的有效 Pending 登记及可恢复关联 |
| StartAuthorized / Waiting / Unknown -> Resolved | 接受来源合格且无冲突的确定证据; Outcome 是否提交另过终结守卫 |
| StartAuthorized -> Unknown | 确认临时控制权失效且仍无有效等待或确定证据; 保留 grant 与可能已执行的事实 |
| Unknown -> Waiting | 合法迟到 Pending 恢复可继续的等待关联, 不要求旧 lease 仍有效 |

生命周期不是报告种类的最后写入投影. 对普通报告接收和控制命令, 以下行为也必须满足:

| 情况 | 投影与持久事实 |
|---|---|
| Prepared 重新领取或替代 | 重新领取不改 phase; 替代建立新的 Prepared, 旧尝试不伪造完成 |
| Waiting 的 lease 到期 | 临时权限失效, phase 仍 Waiting, 关联仍有效; 到期本身不是 Unknown 的依据 |
| Resolved 收到迟到 Pending | 保留原确定结果与 Resolved; 保存合法报告, 不回退为 Waiting |
| NotFound | 仅保存负面观察, 不改变 phase/已有 Knowledge, 不证明 NotExecuted |
| 可靠 NotExecuted | 保存协议依据并可投影 Resolved; 它不是 Failure, 新尝试和停止仍分别验证 |
| 矛盾报告 | 保留最近有依据的 phase/Knowledge 与全部证据, 标记独立冲突; 不自动协调或覆盖结果 |
| 相同报告重投 | 补确认, 不重复状态变化或同一 History |
| Closed 或旧非当前尝试的合法报告 | 继续保存证据及必要审计; 不重开 Intent, 不直接抢占 Outcome |
| CancelIntent | 终结 Intent, 不把其各 Execution 伪装成外部已取消或已完成 |

以上描述对应首版报告/lease/替代规则, 不是无条件的状态更新许可. 每次处理仍验证来源, 关联与对应命令守卫,
不存在 grant 的 Worker/回调完成不能靠目标 phase 绕过授权. 其他 Operation 特定转换与后置协调需明确契约,
不能从未列出的状态边推断合法. 现有模型只在其来源/资源假设内验证这些关系, 真实入口另做符合性测试.

### 3.3 资格与 lease

- 生命周期与直接成为 Outcome 候选的资格正交. 撤权不伪造尝试结束, 不阻止保存证据.
- 从未启动但已撤权的尝试可以保留为 Prepared; 不要求为归档它伪造完成结果.
- 同一 Intent 第一阶段默认最多一个当前被授权执行的尝试, 不提供主动 hedging. Intent 使用可为空的 current_execution_id
  表达当前关联; 正常完成还须满足 Open, 来源, 证据等守卫.
- 替代尝试时原子建立新 Execution 并切换当前关联. 旧尝试不直接赢得 Outcome, 但保留真实进展和报告.
- 已撤权的尝试不能直接赢得 Outcome, 即使它报告成功且 Intent 仍 Open. Authority 可以按明确的 reconciliation
  流程验证使用其证据.
- Worker lease 到期不自动撤销 Execution 的结果接受资格. Authority 可以接受未撤权尝试的合格迟到结果.
- 到期撤除相应临时控制权限; 已授权而无可靠结果或等待登记时可标 Unknown, 保留当前尝试资格. 先协调, 满足安全条件后才替代,
  不立即重新执行.
- Waiting 不依赖常驻 Worker, Worker lease 到期本身不能将其判为 Unknown.
- 替代尝试的授权必须明确处理旧资格并验证安全重试条件. lease 的 Authority 时间, generation, 失效及重启原则见
  [lease 与权限 SPEC](leases-and-permissions.md); 首版存储与重投细节见 [存储命令契约](storage-command-contracts.md).

## 4. 启动, 派发和恢复

- Worker 调用可能产生副作用的 Handler 前必须取得已持久化的 Start Authorization.
- Start Authorization 绑定可序列化的 Worker incarnation. 重启产生新 incarnation, 不能直接继承旧许可重新调用.
- 授权已提交而外部调用尚未发生时崩溃也可能产生保守 Unknown; 没有 Running 报告不能证明未执行.
- 派发重投保留同一 Execution 身份; 报告重投只重投证据; 外部重新执行属于新的安全决策. 三者不得混同.
- 同一 Execution ID 不是外部幂等保证. 启动请求的 token 身份, 原许可回复与领取重投规则见首版存储命令契约.
- 未授权启动的 Prepared 可以重新投递; Authority 原子确认从未授予启动许可且旧领取资格失效后, 可让新 Worker 领取同一
  Execution.
- 已授予许可则新 incarnation 不接续旧许可调用 Handler. 再次执行须建立安全的新尝试; 不依据 Worker
  声称未收到许可或未执行判断.
- 待处理工作必须能从持久事实重新发现. 调度唤醒与 Outcome 通知用于降低延迟, 不是唯一恢复依据.

## 5. 报告与冲突

- 可接受的报告必须验证身份, 来源和操作契约. 逻辑身份, 相等性和预算见 [值与消息](persistent-values-and-messages.md),
  来源与回调核验见 [Handler 契约](operation-handler-contracts.md); 具体 codec/凭据仍待实现验证.
- Durable 模式不得在报告证据落盘前确认已持久化.
- 已持久化, Outcome 已接受, 未采用/待协调是不同含义; 一次响应可同时携带多个已成立的含义.
- 已撤权报告可以保存后确认未采用, 不要求发送方必须赢得 Outcome 才能停止重投.
- 重复报告可以去重, 矛盾报告不得覆盖或按最后写入/时间戳选择结果.
- 已知冲突且尚无 Outcome 时, 阻止未经协调的自动终结. 已有 Outcome 时保留冲突, 不改写结果.
- 未协调冲突独立于生命周期持久化. 冲突报告保留最近一次有依据的生命周期投影, 不按最后报告回退或改判; Resolved
  可以同时存在未协调冲突. lease 等独立协议转换仍按自己的守卫执行.
- 解除冲突须明确 reconciliation, 不覆盖原始证据, 不以新报告自动清除争议. 显式 Cancelled 仍遵守原有控制面规则.
- 协议不能预知未来报告. 报告确认前 Worker 崩溃且未保存自身证据时, 仍可能 Unknown.

## 6. Outcome

### 6.1 分类与来源

| 分类 | 定义 |
|---|---|
| Succeeded | 接受操作契约定义的正常完成结果, 不要求业务结果正面 |
| Failed | 接受明确错误, 或依据已知事实与策略决定无法正常完成 |
| Cancelled | 接受停止继续处理 Intent 的逻辑决定, 不证明外部停止或回滚 |

Unknown, 超时和预算耗尽本身不是终态 Outcome. 审批拒绝等业务结果可按契约作为正常完成数据.

Outcome 属于 Intent. 普通 Handler 完成保留 Execution 关联; 未执行就取消, Authority 策略终结等不需要虚构 Execution. 每个
Outcome 均应有明确来源, 理由及必要证据关联; 不允许无依据成功.

### 6.2 接受守卫

任何终结必须验证 Intent Open, 来源和资格有效, 并满足对应操作契约或控制面权限. 已知未协调冲突阻止自动终结.

Failed 至少还要求:

1. 明确的错误或终结依据.
2. 策略决定不再尝试.
3. 没有未解决且仍可能改变逻辑结果的不确定性.

旧非当前/已撤权尝试的成功证据尚未协调时, 当前尝试已知失败也不能普通提交 Failed. 必须按 Operation
契约明确采用或排除旧成功证据; 旧成功不能直接抢占 Outcome, 也不能因失去资格而被忽略.
首版保留该阻塞, 不提供处置命令. 后置协调的提交, 身份与审查规则见 6.4; 具体字段及 SQL 映射另行设计.

Failed 不证明不存在部分外部副作用. Cancelled 可以终结未解决 Intent, 但不将未知外部事实改写为已知失败或已停止.

取消和合格完成竞争时, 第一个通过全部验证并完成权威事务提交的决定获胜. 不按 Worker 时间戳倒推优先级,
不允许取消请求天然覆盖已提交成功.

### 6.3 原子终结

- Outcome, Intent Closed 与对应终结历史必须在一次本地事务共同提交.
- 普通合格完成默认同事务保存报告, 更新 Execution, 插入 Outcome, 关闭 Intent 和写历史.
- 已撤权, 冲突或待协调报告可以仅持久化证据而不终结 Intent.
- 存在 Outcome 后任何新候选都不能产生第二个 Outcome. 迟到事实仍可保存.

最小停止/重试策略区分失败事实与终结资格, 参见 [正常闭环模型](../quint/beamletNormalUse.qnt).
已具备停止依据的合格失败同一步保存报告, Execution, Outcome/Closed 和 History.
核心原语仍保留先存失败事实, 后作停止决定的处理上下文. 首版最小策略的额度, 提前停止与错误分类边界见
[Handler/恢复契约](operation-handler-contracts.md); 不扩展为通用策略治理算法.

### 6.4 证据协调命令(后置)

以下约束用于未来的协调/治理能力. 首版没有人工采用/排除接口, 证据不足时保持 Open.

#### 决定与依据

协调决定引用具体报告, Operation 契约依据, 理由及处理主体, 明确采用的结果和排除的证据对本次判断的影响. 原始 Report
不覆盖, 不以永久"已协调"标志代表所有证据已经处理.

Authority 在同一 Intent 原子边界重验当前证据和资格, 保存协调 History, 再解除对应阻塞或提交 Outcome. 新证据须重新判断,
不能由旧处置自动涵盖. 审查过期按判断版本校验; 判断作用域, 具体相关变化清单与 SQL 表示仍待细化.

可由明确登记且条件可验证的 Operation 规则自动提出协调, 也可由获授权主体显式提出.
缺少适用规则或证据不足则保持待协调. 两类入口都遵守相同证据, 资格, 原子提交和审计规则, 不允许改写已有 Outcome.

人工决定的审查上下文在提交前已过期时拒绝并返回当前上下文, 不静默改写决定.
自动规则可以对新上下文重新求值并提出新的可审计决定. 普通心跳不属于影响判断的证据/资格变化.

#### 命令身份与重投

每个协调命令具有 Intent 范围内稳定 ID. 原子提交须保存命令身份, 领域内容与原处理结果, 并与决定及其 History 一致. 同
ID 同内容的重投返回原结果, 不重执行, 不新增同一决定审计; 同 ID 不同内容拒绝. 已提交命令即使原快照已过期或 Intent 已
Closed, 也能被识别为重投, 不按新命令重新作资格判定. 这不会让旧决定处理新证据.

经过权限和格式校验后的明确领域拒绝也原子保存命令身份, 请求内容, 当时拒绝结果和审计. 重投复用原拒绝, 不重新判断;
重新审查须用新 ID. 拒绝不制造证据处置决定或 Outcome. 通信故障, 未提交的数据库异常及入域前校验失败不伪装成已提交领域结果.

#### 权限与保留

新决定与原结果读取使用各自当前权限. 已失去提交权限但仍可读取时, 重投返回原结果; 失去读取权限后拒绝返回内容,
保留原命令身份与结果, 不重新执行.

Intent 仍被保留时, 已处理命令的身份, 相等性所需信息及原结果持续保留, 不默认 TTL 清除; Closed 也适用.
归档或清理须保证旧 ID 不重新可执行, 并定义原结果查询能力.

#### 判断版本

协调命令携带审查时判断版本, Authority 在同一 Intent 原子边界比较当前版本后重验决定. 相关持久变化递增版本;
心跳, 重投和纯拒绝审计不递增. 版本相同仍须验证具体报告, 契约依据和当前权限. 已处理命令的重投先识别原结果,
不重新校验为新决定.

判断版本保护新决定的提交时刻. 已接受处置的后续适用范围按其证据和资格依据判断, 不因该决定自己的版本递增而立即失效.

#### 冲突与全部排除

冲突协调须显式覆盖本次判断相关的全部冲突报告, 逐项说明采用/排除及契约依据. Authority 原子保存处置, 解除对应阻塞,
条件满足时提交成功或失败 Outcome. 原始报告, 冲突历史保留; 新证据重新判断.
历史上发生过矛盾与当前是否仍有未解除阻塞分别表达, 不靠清除历史标志假装未发生冲突.

具备逐项契约排除依据时, 可以排除全部相关矛盾报告并完成这组冲突的审查处置, 但本次结果判断仍未知, Intent 保持 Open.
不因此生成成功/失败 Outcome, 不把未知改写成未执行, 不自动授权重试. 已授权未知尝试的风险仍须独立排除;
原报告, 历史冲突, 命令原结果与审计保留. 新证据须重新判断.

#### 取代与规则版本

新决定改变先前证据处置时, 引用被取代的旧处置及对应范围. Authority 原子重验版本, 引用, 证据, 契约与权限,
保存新决定, 取代关系和审计并更新当前适用关系. 只取代明确范围, 不隐式覆盖范围外的处置;
旧决定, 原始报告与命令原结果继续保留. 被取代决定的原命令重投仍返回原处理结果, 不重执行或返回最新 Outcome.

自动决定绑定具体规则身份和语义版本. Authority 原子核验该确切版本仍被登记且条件满足, 不默认最新版本或静默迁移旧请求.
历史决定按当时版本解释, 原命令重投按当前读取权限返回原结果; 新求值形成指定规则版本, 当前上下文及新命令身份的新决定.
语义版本与代码发布版本分别表达.

普通规则版本退役只阻止新提交, 不自动撤销已接受处置, 不单独改变当前判断或推进 Judgment Revision.
旧处置仍受证据范围, 实际适用条件和显式取代关系约束. 需要撤销既有处置时,
使用明确, 可审计的操作改变当前判断并推进判断版本; 旧决定, 原命令结果与已有 Outcome 保留.
规则登记和撤销的具体工程协议仍待细化.

#### 撤销

撤销只移除明确范围的当前处置, 不恢复更早被取代处置. 该范围重新等待判断, 按原始证据重新确定必要阻塞;
范围外的处置保留. 再次采用旧结论须形成新的合格决定. 撤销自身不产生 Outcome 或危险重试许可, 历史与原命令结果保留, 已有
Outcome 不改写. 明确撤销改变当前判断并推进判断版本; 具体命令字段和工程协议仍待细化.

撤销作为独立领域操作复用协调命令的同一 Intent 身份域. 新撤销携带新命令身份, 明确目标/范围与当前审查版本,
首次接受原子保存关系, 命令原结果, 审计及版本变化. 已处理同身份同内容请求按当前读取权限返回原成功/领域拒绝结果,
不重新执行或转向后来建立的处置; 同身份不同内容 (包括协调与撤销互换, 改变范围) 冲突拒绝.
已知身份查找先于首次提交资格/审查核验, 不因新证据, Closed 或规则/权限变化改写原结果.

普通协调权限不自动包含撤销权限. Authority 首次接受撤销时独立核验主体对具体目标/范围的授权,
再检查依据与审查版本. 自动规则须明确允许撤销且条件合格; 原命令结果读取仍只按当前读取权限判断.
两类权限可授予同一主体, 不要求新角色框架, 不赋予修改历史或已有 Outcome 的能力.
撤销专属授权尚无 Quint 区分场景或真实鉴权实现.

具体相关变化清单, 权限策略, 身份绑定, 决定身份与关系表示, 规则语义版本表示/登记/退役与历史解释材料保留, 条件核验,
相等性编码, 归档/清理与鉴权原子协议尚待设计. 自动规则声明不是证明, 人工决定也不等同于任意状态修改.
第一阶段不引入通用协调 Workflow.

## 7. 必须保持的 Safety 性质

| 标识 | 性质 |
|---|---|
| S1 | 每个 Intent 至多一个 Outcome |
| S2 | Intent Closed 当且仅当存在 Outcome |
| S3 | Outcome 一旦提交不可替换或修改 |
| S4 | Closed Intent 不再授予新尝试或启动许可 |
| S5 | 已明确撤权的 Execution 不直接赢得 Outcome |
| S6 | 启动许可先于合规 Worker 的外部执行, 且绑定 incarnation |
| S7 | 同一 Intent 默认最多一个当前被授权执行的尝试 |
| S8 | Unknown, 失联, 超时和预算耗尽不单独授权危险重试或失败终结 |
| S9 | 权威终结与终结历史原子一致 |
| S10 | Durable 已持久化确认不先于证据持久化 |
| S11 | 证据处置的取代只影响明确范围, 旧决定和命令原结果保留 |
| S12 | 普通规则退役不自动改变既有处置, 当前判断版本或命令原结果 |
| S13 | 撤销只移除指定范围当前处置, 不自动恢复旧结论, 生成终结或危险重试许可 |
| S14 | 协调与撤销共用命令身份域; 撤销重投不执行新操作, 不转向新处置, 原成功/拒绝结果保留 |

S6 是 Worker 合规与授权协议的性质, 不是数据库独自保证的外部副作用性质. S7 不是物理外部执行互斥.

## 8. 验收场景

以下断言用于实现验收; 抽象模型的实际覆盖见 [模型边界](../quint/README.md#模型边界).

### 执行与恢复

| 场景 | 必须满足的断言 |
| --- | --- |
| 两个合格完成, 或取消与完成竞争 | 首个通过守卫的提交获胜; 最多一个 Outcome, Closed 与 Outcome 同提交 |
| 授权后调用前崩溃, Worker 重启或旧许可晚到 | 不推断未执行; 新 incarnation 不继承许可, 危险重试被阻止 |
| Prepared 派发/领取回复丢失 | 保留原 Execution/分配身份, 启动前重验资格 |
| 外部完成后报告/回执丢失 | 按原报告身份重投, 不重复外部执行或 Outcome |
| Outcome 已提交但通知丢失 | 可读取并复用原结果 |
| durable Pending 后所有进程退出或 lease 到期 | 保留原完成关联, 不重复创建外部请求, 不仅因到期制造 Unknown |
| Resolved 后迟到 Pending/矛盾完成 | 确定投影不回退; 冲突独立保存, 已有 Outcome 不变 |
| 已撤权旧尝试成功, 当前尝试失败 | 两种到达顺序均保留旧成功阻塞, 不普通提交 Failed; 显式取消仍单独验证 |
| Unknown 且预算耗尽 | 不自动 Failed, 不据此授权危险重试 |

### 后置协调与治理

| 场景 | 必须满足的断言 |
| --- | --- |
| 采用/排除旧成功或矛盾报告 | 明确完整证据范围与依据, 保留原始报告, 原子保存处置/审计及合格 Outcome; 全部排除仍可 Open/Unknown |
| 审查后新证据/资格变化, 或并发处置 | 拒绝过期决定并返回当前上下文; 不静默改写批准内容, 心跳/重投不使判断过期 |
| 判断版本相同但权限/规则/条件不合格 | 仍拒绝新决定; 自动规则须登记且条件可验证, 人工决定须获授权 |
| 同命令重投, 包括响应丢失/重启/Closed/新证据到达后 | 返回原成功或领域拒绝, 不重执行; 同 ID 异内容冲突, 入域前失败不占身份 |
| 已拒绝请求后来条件改善 | 原身份仍返回原拒绝; 重新审查使用新 ID |
| 提交权限或读取权限变化 | 新提交与原结果读取分别验证当前权限; 拒绝读取不删除身份或原结果 |
| 处置缺少/越界/复用取代引用 | 不隐式覆盖; 只改变明确范围, 保留旧决定, 范围外绑定与原命令结果 |
| 多规则版本, 退役与重新求值 | 按确切版本检查; 普通退役不改变旧处置/判断版本, 新求值使用新身份, 原结果按当前读取权限可读 |
| 撤销取代后的处置或部分范围 | 不恢复更早决定; 未涉及范围保留, 原证据恢复必要阻塞; 撤销本身不终结, 不授权重试 |
| 撤销后新处置建立, 原撤销重投 | 返回原结果, 不转向新处置; 协调/撤销共用命令身份域, 首次接受独立检查撤销授权 |

## 9. Liveness 与工程边界

不承诺所有 Intent 自动得到 Outcome. 进展保证须明确依赖 Authority/存储最终可用, 调度公平性,
传输重投, Handler 或人工响应等假设. 不可查询且不允许重复的 Unknown 可以长期未解决.

物理约束, 驱动事务, codec, 认证与部署持久性须按 [实现路线](implementation-roadmap.md) 验收.
Authority 迁移另需一致切点, 旧方撤权与新方激活协议.

## 10. 存储与调度边界

使用 intents / executions / outcomes / reports / history 五类逻辑实体, 物理表数由实现选择.
同 Intent 的资格, 证据与终结共用原子保护; 不要求不同 Intent 全局串行.
领域规则接收显式快照, 命令和时间, Storage 防止事务外的过期判断被强行提交.

工作从持久事实扫描发现, 通知仅用于唤醒; 不强制 Outbox 或通用 Job 模型.
调用方持久保存业务恢复集合, 通过领域读取接口重建进度, 无须遍历全部 Runtime 表.
纯领域测试使用快照, 存储符合性测试分别使用真实 SQLite/PostgreSQL.
具体命令与候选发现见 [存储契约](storage-command-contracts.md).

## 11. History 的可解释性契约

History 以 append-only 事实解释重要变化, 与对应状态同事务保存.
逻辑材料如下; 物理字段与排序编码由实现设计, Quint 的 Audit 不是产品字段全集.

每份重要审计事实须能回答以下问题; 可引用同事务保存且持续可读的定义/报告/绑定, 不必复制全部正文:

| 材料 | 含义 |
| --- | --- |
| 稳定记录身份与 collection/Intent | 定位审计事实, 不能因恢复或重投生成另一次同义决定 |
| 事实种类与受影响实体 | 区分状态转换, 资格变化, 证据保存/冲突, 拒绝与终结; 引用相关 Execution/Outcome/Report |
| 前后状态或相关修改摘要 | 只记录实际变化的维度; 不强行给迟到报告/拒绝伪造 from/to 转换 |
| 主体与执行关联 | 已核验 actor/来源, 必要 Worker/incarnation/generation 与 Handler/资源绑定引用 |
| 理由与依据 | 拒绝码, 停止/重试依据和版本化契约引用, 足以解释为何接受/阻塞 |
| 记录时间与来源时间 | Authority 记录时间用于诊断; 外部发生时间是来源声明, 不用来倒推权威优先级 |
| 提交组与组内次序 | 标识同一 Intent 一次原子提交中的多个审计事实, 关联状态/报告/Outcome 写入 |
| 解释版本 | 保存事实格式/理由版本及原契约解释材料, 不能因代码升级修改历史含义 |

首版不需要全系统总 Sequence. 每个 Intent 在同一原子保护内分配非复用的提交组次序, 再按组内位置排序;
次序用于解释已提交事实, 不是授权凭据或治理 Judgment Revision. 精确计数范围和存储方式在物理设计时确认.
同 Intent 的并发写入按其权威提交顺序解释, 不按不同节点的墙钟时间排序.
跨 Intent 不承诺一个全局先后顺序; trace/request 关联只辅助诊断, 不建立跨 Intent 事务.
不声称 SQL 时间戳等于精确的实际 commit 时刻, 时钟回拨不能改变已保存的相对次序.

必须保留创建, 领取/代次改变, 失效, 启动, Unknown, 有效等待, 报告/冲突, 替代依据和终结的重要事实.
普通心跳, 轮询和完全相同报告的重投不重复追加领域 History. 同身份不同内容首次发现时保留独立冲突材料,
重投同一冲突正文可以补确认, 不制造无限相同审计. 入域前认证/格式失败使用受控安全日志, 不据此占领域身份.
需要解释的领域拒绝可记录无状态变化的审计, 但不默认套用后置协调命令的完整拒绝结果缓存.

状态和对应 History 一起提交, 回滚后两者均不可见; commit 后响应丢失通过原身份/已提交事实恢复.
History 不成为执行事实的替代存储, 不靠重放它恢复每次续租或 Agent 上下文.
首版随保留的 Intent 保留 History, 必要报告, 身份及解释材料, 不提供 TTL 删除或身份复用.
通过有界读取/分页, 正文引用, 避免心跳审计控制增长; 接收能力耗尽返回存储/容量异常, 不伪造 Failed.
未来归档或脱敏须单独定义仍能解释什么, 如何防止旧身份再执行, 不能偷偷改写既有结果.

验收: 检查多条关联写入的提交/回滚, 同内容和冲突重投的审计去重, 无状态变化的拒绝/迟到事实,
时钟回拨后的次序, 两个 Coordinator 同 Intent 提交组唯一性, 旧版本材料读取, 以及 History 读取权限和凭据不泄露.
[History 模型](../quint/beamletHistory.qnt) 独立检查两 Coordinator 草稿/提交重验, 组次序, 状态/增量事件原子公开,
回滚与重复报告不增组. group 的事件列表位置抽象组内次序, actor/command/固定解释版本与前后快照解释来源和变化.
该例只选择有限命令与提交组, 未验证任意历史事件序列, 完整字段预算, 提交组物理编码或真实 SQL 次序.
