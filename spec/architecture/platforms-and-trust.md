# 平台、角色与信任

## 1. 适用范围

定义跨平台应用接入边界、客户端与 Run 生命周期的区别、节点角色，以及运维方管理的可信集群前提。

## 2. 接口签名

~~~text
ApplicationGateway.handle(authenticated_context, command_dto) -> receipt | projection | error
RuntimeBootstrap.start(validated_application_config) -> supervised_roles
ProjectionReader.read(run_ref, query_with_cursor_and_limit) -> revisioned_projection
~~~

网关与启动名称表示目标职责，不引入新的网关框架。公共命令采用[计算与 Effect](./computation-and-effects.md)中的接口，不直接访问后端或任意 RPC。

## 3. 契约

| 交互终端 | 交互方式 | 计算 / 执行 | 权威存储参与 |
| --- | --- | --- | --- |
| CLI / fuelen/owl | 本地或联网适配器 | 可配置的 BEAM 宿主角色 | 在满足存储条件时独立配置 |
| TUI / agentjido/term_ui | 本地或联网适配器 | 可配置的 BEAM 宿主角色 | 同上 |
| 桌面 / elixir-desktop | 原生或基于 Phoenix 的宿主 UI | 可配置的宿主角色 | 同上 |
| Android / Mob | 设备上的 Elixir / BEAM UI | 可配置的设备角色 | 同上，须通过平台验证 |
| Web / Phoenix | 浏览器通过经过认证的 Phoenix 接入边界访问 | Phoenix 或其他 BEAM 宿主；独立于 LiveView PID | 独立配置 |
| 服务端节点 | 无界面服务、应用或网关 | 可配置的宿主与资源角色 | 稳定宿主可作为权威节点候选 |

一个节点可以同时承担交互、计算、执行和权威角色。存储不复制到每个连接节点。使用前验证角色配置以及所需的兼容计算定义与提供者代码。

不假定浏览器拥有 BEAM 计算宿主。UI 或视图断连不终止 Run 标识与历史；联网原生应用配置后可以承载计算。设备进程丢失或连接中断，由相同的权威层与执行尝试协议处理。

没有权威写入路径的节点，不能确认新的集群持久化推进。此前已获授权的外部操作仍可以完成；断连不是取消证据。

### 接入边界 DTO 与授权

| 字段 / 边界 | 约束 |
| --- | --- |
| command_id / 输入键 | 每个逻辑操作使用稳定二进制键；以不变的规范化数据复用 |
| run_ref / boundary_ref / invocation_ref | 不透明、已验证引用；逐操作检查访问权限 |
| 调用裁定 | 验证 decision、expected_execution_revision、来源与有界证据；区分审计追加、终局裁定和一次性重复执行权限 |
| 操作 / 定义 / 数据配置 / 版本名称 | 二进制，解析到已注册且允许使用的代码或契约 |
| 载荷 / 选项 | 已验证模式与有界可移植数据 |
| 查询游标 / 限制 | 不透明游标、正数有界页大小、明确的投影修订号 |
| 资源绑定 | 验证标识、权限与实际可用性 |
| 响应 | 共享回执、错误与投影解码器；UI 不独立解析账本 |

在相应应用或提供者边界，对创建、输入、控制、检查、导出和资源使用实施授权。已验证数据不构成加载或执行模块的指令。

成员关系与已加载代码由用户或运维方控制，并被视为可信。Scope 隔离用于选择服务，不用于限制恶意代码或已加入集群的恶意节点。权威协议不提供拜占庭共识。

按需采用标准安全 BEAM 分布式机制，以及应用认证与授权。基础层不新增自定义加密成员协议或不可信节点沙箱。第三方控制的执行域需要单独的隔离与协议工作。

### OTP 生命周期

使用监督者、已注册的本地计算宿主、任务与工作进程监督者，以及提供者管理器，承担实际生命周期、并发与故障职责。执行工作进程重启必须产生新的 execution_owner_ref，不复用旧 Attempt 授权；纯步骤工作进程的异常与资源故障按 FailRun 契约处理。Registry、pg 与发现机制仅提供线索。持久化记录、纪元、收件箱和发件箱才是权威事实；不存在持久化邮箱或进程栈快照。

## 4. 验证与错误矩阵

| 条件 | 接入边界行为 |
| --- | --- |
| 未知或未授权客户端，或未获授权的 Run 操作 | unauthenticated / forbidden；不修改状态 |
| 无效模式、任意 MFA / 模块、不安全项 | invalid_data；不执行 |
| 未安装兼容计算定义或提供者 | incompatible_version / unavailable_resource |
| 视图或终端连接中断 | 依据 Run 标识与修订号重连或查询 |
| 计算或执行宿主消失 | 应用权威恢复与不确定性规则，不复用 PID |
| 权威写入不可用 | 不返回虚假持久化回执 |
| 使用缓存投影授予所有权或执行权限 | 契约违规 |
| 将不可信节点作为普通成员 | 超出初始信任范围 |

## 5. 正例、基础场景与反例

正例：移动端 UI 与计算角色、桌面提供者通过稳定的服务端权威节点协作；关闭视图不删除计算历史。

基础场景：服务端承载全部角色，其他终端通过共享 DTO 交互。

反例：向浏览器提供分布式 cookie；将 Run 生命周期绑定到 LiveView；或者宣称 Scope 沙箱能限制节点上的代码。

## 6. 必需测试

<a id="s15"></a>

### S15 — 各类终端角色

验证角色矩阵、独立存储分配和共享接口。在后续平台实现测试中，断开并重连 UI、终止计算宿主、断开工作进程连接，验证权威可用性与迟到结果行为。宣称平台支持前，必须测试原生打包、受支持 OTP / Elixir 构建、移动操作系统生命周期与真实网络。

<a id="s16"></a>

### S16 — 信任与授权

测试未认证或未授权的命令、查询、导出和资源绑定请求被拒绝。分别验证调用审计、终局裁定、重复执行许可与原回执查询的授权；同键重试不绕过接入权限检查。断言外部客户端不能成为集群成员，也不能通过数据执行任意已注册或未注册函数。明确说明加入系统的代码被视为可信，Scope 或共识机制不承诺限制恶意成员。

## 7. 错误与正确做法

~~~text
错误：将 LiveView PID 作为持久化 Agent 标识，并在断连时停止历史记录。
正确：通过可替换的视图连接呈现稳定 Run 引用。

错误：要求每个终端投票或存储副本。
正确：独立配置权威成员关系，以及计算、执行和交互角色。

错误：认为 Scope 隔离能使任意第三方节点安全。
正确：加入的节点必须可信；不可信执行需要单独的边界。
~~~
