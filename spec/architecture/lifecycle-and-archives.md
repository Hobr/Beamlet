# 生命周期、后续推进与可移植归档

## 1. 适用范围

定义暂停与恢复、稳定边界分支、可移植导入导出、版本化数据，以及 DTO / 编解码边界。运行中的进程、邮箱、外部文件系统或提供者凭据不是可移植计算快照。

## 2. 接口签名

~~~text
Beamlet.suspend(run_ref, command_id: key, ...)
Beamlet.resume(run_ref, command_id: key, ...)
Beamlet.move(run_ref, target_host_ref, command_id: key, ...)
Beamlet.fork(run_ref, boundary_ref, command_id: key, ...)
Beamlet.export(run_ref, boundary_ref, profile, ...)
Beamlet.import_archive(binary, bindings, profile, command_id: key, ...)

PortableData.encode(term, profile) -> {:ok, binary} | error
PortableData.decode(binary, profile, registered_schema) -> {:ok, term} | error
~~~

修改操作使用[计算与 Effect](./computation-and-effects.md)中的回执与错误契约。编码器与解码器名称表示目标接口，不表示模块已经实现。

## 3. 契约

### 暂停与后续推进

暂停提交后，新的状态推进或执行尝试授权均不得成功。提交顺序在暂停之前的授权仍然有效；绑定的原执行主体可以稍后才开始，也可以在暂停期间完成并记录结果。重复分发与原授权回执查询不允许替代工作进程继承旧 Attempt，具体规则见[执行主体与恢复](./authority-and-recovery.md)。

恢复仅改变 open Run 的模式并获取新的推进权限，重新加载状态、输入与推进状态，按收件箱顺序消费已提交结果。finished / failed 不得通过 resume 重启。不得仅因进程重启就重复已完成操作。

ready 状态包含以 Run / 状态修订号为键的纯数据后续推进记录。原 Run 恢复时使用原收件箱、游标和已提交记录，按[输入调度规则](./computation-and-effects.md)消费或明确处置。新分支重建自己的后续推进记录，不导入 PID、闭包或可执行源队列。waiting 需要新的普通输入；finished 保持终态并保留 finish_result。

稳定边界资格在提交该边界时记录：lifetime 为 open 或 finished，progress 为 ready、waiting 或 finished；快照因果相关工作中没有 pending、executing 或 unknown Effect，也没有未消费的权威回复。后续完成不能追溯地将此前仍有执行中工作的检查点变为稳定边界。failed 当前快照不能作为初始分支或导出边界，但可以选择更早保留的稳定边界。稳定性不证明资源或更早执行尝试已经在物理上停止活动。

### 分支标识与归档

创建分支时复制应用状态与选定的已完成历史前缀。源 Run 继续独立执行。新 Run 标识使后续 Effect 标识与源 Run 不同；继承历史保持只读。

分支初始处于 suspended 模式。源 Run 待处理的外部输入队列和运行中的执行尝试不会被激活。新分支的 input_cursor 从 0 开始，queue_seq 重新分配；ready 的新后续推进是新收件箱的第一条记录，waiting / finished 初始没有可执行源输入。引用的子 Run 或资源仍保持为引用；递归复制图或环境需要应用层显式组合。

| 归档清单字段 | 契约 |
| --- | --- |
| format_version | 受支持的正数版本，初始为 1 |
| codec_profile | 已注册的数据配置 ID / 版本 |
| origin | 权威域、Run、边界标识与来源信息 |
| definition_ref | 已注册的逻辑、状态与输入版本 |
| snapshot | 状态、状态修订号、源输入游标、推进状态、lifetime 与 Scope 描述符；finished 包含 finish_result |
| history | 必需历史前缀、已完成结果与派生关系；不包含可执行源队列 |
| resource_requirements | 目标必须满足的逻辑标识、版本与约束 |
| integrity | 可选的记录字节完整性信息；不证明外部事实或授权 |

导入在激活前验证归档并解析代码与资源。它创建 suspended 新分支，并返回基于稳定键的回执；open 分支显式恢复才会激活，finished 分支保持终态，其 resume 返回 run_finished。源输入游标仅保留为来源元数据，不授予消费新分支队列的权限。源 Effect 的执行修订号、Attempt 授权及一次性重复执行权限只能作为只读历史，不成为新分支的可用权限。

归档须包含必需的不可变载荷数据，或使用已验证的持久化引用。缺少数据、资源或代码时，明确返回不执行的结果。导入不安装代码、不复制凭据、不删除源 Run，也不恢复外部副作用。

代码升级或热升级不得静默迁移旧状态或重新解释操作。使用匹配的已注册版本或已声明兼容的目标。未来迁移必须显式、版本化，并保留原始历史。

### ETF 数据配置

初始目标配置为 `etf-data-v1`：标准、未压缩的 OTP ETF，并附带应用层验证。

支持的数据：整数、浮点数、二进制、位串、正规列表、元组、映射，以及允许使用的已有原子。已注册结构体视为具有允许标签与模式的已验证映射。外部名称使用二进制。

递归排除 PID、端口、运行时引用、函数与闭包，改为持久化稳定逻辑引用。编码器不使用 instance-local 选项。编码成功或使用 `:safe` 解码，都不能单独证明应用数据有效。

必须配置以下正数限制：

| 配置键 | 含义 |
| --- | --- |
| max_record_bytes | 编码后单条记录的字节上限 |
| max_archive_bytes | 导入导出的字节上限 |
| max_term_depth | 解码后结构深度上限 |
| max_term_nodes | 解码后结构节点数量预算 |
| decode_timeout_ms | 受监督解码器的时间限制 |
| decoder_heap_words | 解码工作进程的堆限制 |

这些是必须设置的有界参数，不是已确认的生产默认值。通过测量确定各角色与应用的默认值；启动或导入时拒绝缺失或无界配置。工作进程限制是资源防护，不是恶意代码沙箱，也不保证严格的 RSS 上限。

导入在解码前实施字节限制，对该配置拒绝压缩或顶层 instance-local 包装；随后使用 safe + used 解码，确保消耗全部字节，并执行递归数据验证和已注册模式检查。保留或导出前，通过标准编码规范化已接受的逻辑数据。不需要完整的自定义 ETF 解析器或序列化器注册表。

编码与规范化发生在序列化边界，先于条件存储命令。副本应用已捕获数据，不通过自己的重新编码、时钟或随机数派生标识。

记录摘要必须标明其字节、数据配置与版本方案。跨 OTP 的逻辑相等不能假定存在通用的规范 ETF 字节表示。权限与来源验证独立于校验和与解码。

提供者必须遵守声明的响应边界，或提供已验证的数据引用。超大或格式错误的结果不得静默截断；外部操作的结果未记录时，仍保持不确定。

<a id="prefix-audit"></a>

### 已评审补充：只读前缀与终态审计

稳定前缀是用于检查与显式派生的已提交值，不是执行权限。源 Run 随后失败或保留未知执行，不改变更早已记录边界的资格；新分支只继承该选定因果前缀，仍使用新的队列、标识和当前权限。稳定性不证明外部旧主体已经停止。

failed 当前状态与未知、迟到观测、裁定来源和未处理回复属于保留审计信息。检查不激活工作，原授权观测记录不恢复计算；不新增终态 settlement、取消或自动清理未决证据。修复业务通过更早稳定边界显式派生，不能从 failed 当前快照隐式 resume 或移植其活动授权。

## 4. 验证与错误矩阵

| 条件 | 行为 |
| --- | --- |
| 暂停命令与执行授权竞态 | 由权威提交顺序决定；不宣称追溯取消 |
| 分支边界为 failed 快照，或存在未处理完毕的 Effect / 完成结果 | not_stable |
| 对 finished / failed Run 请求恢复 | run_finished / run_failed；保持终态 |
| 缺少源历史前缀或检查点数据 | invalid_archive / unavailable_data |
| 格式、数据配置、模式或代码不受支持 | incompatible_version；不激活 |
| 目标资源或权限不满足要求 | unavailable_resource / forbidden；不执行 |
| 不可移植项、格式错误或尾随字节 | invalid_data |
| 数据过大、结构过深、项过多，或超出解码器资源限制 | resource_limit |
| 未知原子需要创建，或需要安装代码 | 安全拒绝；不自动创建或加载 |
| 数据配置不允许压缩或 instance-local 包装 | unsupported_encoding |
| 已有导入键对应的逻辑归档或绑定改变 | key_conflict |

## 5. 正例、基础场景与反例

正例：对象处理 Run 记录读取数据，提交 ready 状态，导出该稳定点，导入为 suspended 新分支，验证绑定后恢复，并产生新的写入调用请求。

基础场景：导出并导入处于 waiting 的 Agent 轮次边界；导入分支等待新的用户输入。

反例：恢复旧 PID、解码任意函数、重复已完成历史前缀中的操作、克隆源 Run 的待处理输入或执行尝试队列，或者静默选择不同模型或资源。

## 6. 必需测试

<a id="s5"></a>

### S5 — 生命周期覆盖

在存在待处理与已完成工作的情况下，跟踪移动、暂停、恢复、审核、稳定分支和归档导入导出。验证记录中的计算定义与配置版本解释，以及明确的不兼容行为。

| 初始条件 / 事件 | 必须提交或保留 | 禁止行为 |
| --- | --- | --- |
| finish 与新输入提交竞争 | 按提交顺序接收并保留未处理处置，或返回 run_finished | 确认接收后静默删除输入 |
| 定义故障与宿主接管竞争 | 只有当前纪元的 FailRun 可以提交；保留既有 Effect | 旧宿主使新宿主的 Run 失败或生成部分状态 |
| finished / failed Run 请求 resume | 终态、返回值 / 故障原因和历史不变 | 重新调用 step 或创建新 Attempt |
| failed Run 仍有已授权工作 | 接受合法观测并保存未处理回复；可从更早稳定点分支 | 宣称外部工作已取消或将失败快照激活 |

<a id="s13"></a>

### S13 — 稳定分支与标识

源 Run 当前仍有未完成工作，从更早记录的稳定点创建分支。断言历史前缀与状态保留、新标识独立、源 Run 继续运行、不执行历史操作，且不复制活动队列。拒绝仍有执行中工作或未消费完成结果的检查点。

<a id="s17"></a>

### S17 — 可移植激活

将稳定的 ready / waiting / finished 快照导出并导入兼容目标域。新分支初始暂停；ready 重建新的数据式后续推进记录，waiting 接收新输入，finished 保持终态与 finish_result。断言本地游标从 0 开始、后续推进具有新输入标识、不继承 Attempt 或重复执行权限，且 finished 的恢复被拒绝。缺少代码、模式或资源数据时阻止执行，不隐式安装，也不修改源 Run。

<a id="s18"></a>

### S18 — ETF 边界

对每种支持的数据类别执行编码与解码往返验证。拒绝嵌套运行时句柄与函数、格式错误或尾随数据、不支持的编码、未知模式或原子创建，以及所有超出配置大小或结构限制的情况。跨受支持工具链比较逻辑值，不依赖规范字节相等。运行时原型必须测量解码器资源行为。

<a id="s19"></a>

### S19 — 暂停与执行授权竞态及回复保留

在请求执行授权和步骤提案之前与之后提交暂停。断言随后所有新授权与推进均失败，此前获授权工作的完成结果仍可提交，重启后保留，恢复时仅消费一次。不得断言外部操作已取消。

| 提交顺序 / 故障 | 必须提交或保留 | 禁止行为 |
| --- | --- | --- |
| Suspend 先于 AdmitAttempt | 暂停模式；授权失败且无新 Attempt | 用旧编排权限绕过暂停 |
| AdmitAttempt 先于 Suspend，原主体稍后才调用 | 原授权有效、结果正常记录 | 因新 Run 纪元撤销已提交授权 |
| Suspend 后原主体消失，新主体试图继承授权 | unknown 证据；恢复前不授权新 Attempt | 用旧授权回执让新主体调用 |
| 暂停期间终局结果到达或 settle 提交 | 原子保存结果与回复；恢复后按顺序消费一次 | 暂停期间执行业务步骤或生成第二条终局回复 |

## 7. 错误与正确做法

~~~text
错误：将 :sys.suspend(pid) 视为持久化暂停契约。
正确：提交控制模式与纪元；重建运行时执行主体，保留权威结果。

错误：binary_to_term(bytes) -> 启动归档提供的模块。
正确：限制输入 -> 受监督的 safe / used 解码 -> 验证数据、模式、注册表与资源 -> 创建暂停的新分支。

错误：反序列化源 Run 的后续推进函数，或复制其收件箱。
正确：恢复推进状态数据，创建新的分支本地后续推进记录。
~~~
